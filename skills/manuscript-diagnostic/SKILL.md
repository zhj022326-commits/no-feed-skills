# 稿件综合诊断

把用户提交的稿件分析成《稿件综合诊断报告》。理论真源是 `references/theory/内容生产综合模型.docx`；`references/theory/内容生产综合模型.md` 是同一文件的可检索文本副本。执行时必须读取当前 Skill 附带的完整理论文本，不能只凭本文件或记忆判断。

## 适用范围与输入

- 用户提供完整稿件、可读取的稿件文件、开头、提纲或局部正文时可以启动。完整稿件输出完整报告；局部材料输出相应的局部诊断，并说明哪些结论暂无法判断。
- 创作背景、核心观点、目标受众、平台、传播目的、特别关注的问题和产品信息均为可选输入。优先从原文判断；推断要标记，无法判断就写明。
- 只有缺失信息会实质改变关键结论时才问一个必要问题；其余情况直接分析。
- 用户只要求改写、润色、标题、事实核查或其他单项任务时，执行用户所求，不强制生成综合报告。

## 核心约束

1. 方法名称、定义、分类和关系只取自理论文件。不要引入通用作文评分或其他传播理论，也不要把执行步骤称作理论。
2. 先识别作者要说什么、支持谁、希望谁发生何种判断或行动，再评价稿件。多种传播目的要分主次；无证据时不强行推定立场。
3. 方法是否存在、作者想产生的效果、文本实际能否支持该效果，分别判断。文本效果只是基于原文的推断，不能声称已经测得真实传播数据。
4. 对重要优点、问题和建议给出可定位的原文证据。短引文可配段落位置；不能编造原文、受众反应或作者意图。
5. 不要求每篇稿件使用所有方法。使用状态按需判为：已使用且有效、已使用但效果不足、存在优化空间、未使用但不需要、未使用且存在机会。
6. 允许夸张、荒谬、绝对化和逻辑跳跃。判断其是否服务传播目的、是否被后文以逻辑、修辞、情绪或娱乐形式兑现。不要凭个人文风偏好改弱作者立场。
7. 没有可靠依据的缺点不列为问题；表现良好的模块可以直接肯定。优先处理影响全篇的少数关键问题，并检查建议之间是否冲突。
8. 默认只诊断。除局部示例外，不擅自整篇改写。可疑事实标记“待核实”；用户明确要求时才另做事实核查。

## 执行

1. 读取完整输入和 `references/theory/内容生产综合模型.md`。若用户提供更新版理论，以本次用户文件为准；核对文件可读性与版本后再分析，不沿用旧版结论。需要更新 Skill 资产时运行 `scripts/extract-theory.ps1`，同时保留原始 DOCX。
2. 读取 `references/analysis-workflow.md`，建立稿件画像与证据清单。完整稿件依次检查开头、受众与立场、内容交付、统筹与修辞；只记录有证据且与传播目的相关的方法。
3. 读取 `references/execution-principles.md` 与 `references/boundary-cases.md`，区分理论支持、原文推断和超出理论的建议；处理缺正文、无第三对象、无产品信息等情况。
4. 读取 `references/report-specification.md`，输出《稿件综合诊断报告》。完整稿件包含六大模块；局部稿件保留可分析部分，并清楚标明暂不适用的模块。
5. 交付前检查：理论术语准确；重要判断可回到原文；方法识别与效果评价分开；建议指向具体位置与预期变化；没有重复、互相矛盾或擅自整篇改稿。

## 后续对话

用户追问某个判断时，沿用已有报告和原文证据，解释识别依据或重新评估。用户要求修改指定段落或全文时，按已确认的作者立场和传播目标执行；若稿件或目的实质改变，重新分析受影响部分。
